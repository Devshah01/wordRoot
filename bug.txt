## 🔴 1. Critical Vulnerabilities & Data Loss Bugs

### 1.1 Sync Queue Eviction Causes Data Loss on Non-Network Errors [RESOLVED]
- **Location:** [`app/src/services/sync.ts`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/services/sync.ts#L348-L375) & [`app/src/services/api.ts`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/services/api.ts#L54-L60)
- **Status:** ✅ **Fixed** (Implemented Smart Error Classification & retry counter).
- **Description:** Previously, non-network HTTP errors (such as a 500 Internal Server Error, temporary 401 token issue, or rate limiting) forcibly purged sync items from `sync_queue`.
- **Resolution:** Replaced unconditional chunk removal with Smart Error Classification:
  - `TRANSIENT_NETWORK` / `AUTH_EXPIRED` (401): Keeps items in queue.
  - `TRANSIENT_SERVER` (5xx, 429) & Unhandled errors: Increments SQLite `retryCount` and retains queue items up to 5 attempts.
  - `PERMANENT_CLIENT_ERROR` (400, 422): Evicts only malformed/rejected items.

### 1.2 Primary Key Violation Crash During Guest-to-User Word Migration
- **Location:** [`app/src/db/queries.ts`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/db/queries.ts#L163-L208)
- **Status:** ✅ **Fixed** (Implemented safe conflict check, record merge & duplicate deletion).
- **Description:** When a guest user logs into an existing account, `migrateGuestWordsToUser(userId)` iterates over local words and updates their IDs:
  ```typescript
  await db.runAsync('UPDATE words SET id = ? WHERE id = ?;', [newId, oldId]);
  ```
  If `newId` already exists in the local database (e.g. word was synced from a previous session or created on another device), SQLite throws a `UNIQUE constraint failed: words.id` error inside `withTransactionAsync`.
- **Impact:** The database transaction aborts and `setAuth()` fails completely. The user is stuck in a half-authenticated state where SecureStore token is saved, but store state crashes.
- **Resolution:** Added a check for existing `newId` records before updating. If a conflict occurs, `mergeWordRecords` merges FSRS study statistics, definitions, and dates, replaces the target row with merged data, safely deletes the obsolete guest row, and redirects queued sync actions to `newId`.

### 1.3 Server Sync Upsert ID Mismatch
- **Location:** [`server/src/routes/sync.routes.js`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/server/src/routes/sync.routes.js#L102-L135)
- **Description:** On `action === 'add'`, the server executes `prisma.word.upsert` matching on `{ userId, word: wordKey }`. If the word already exists on the server under a different ID, Prisma updates the word's fields but does **not** update the primary key `id`.
- **Impact:** The client expects the server record to share its deterministic `wordId`. Because the server keeps its old ID, future `update` and `delete` calls referencing `wordId` fail with "Word not found".
- **Remediation:** Ensure upsert logic reconciles `id` field or update `id` explicitly on key collisions.

## 🟠 2. Major Logical & State Management Issues

### 2.1 Stale State in Analog Clock Picker Gesture Handler
- **Location:** [`app/src/components/AnalogClockPicker.tsx`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/components/AnalogClockPicker.tsx#L45-L53)
- **Description:** `displayHourRef`, `displayMinuteRef`, and `isPMRef` are updated inside `useEffect`, which runs asynchronously after React renders. However, `panGesture.onUpdate` invokes `runOnJS(updateHour)` / `runOnJS(updateMinute)` synchronously during touch dragging.
- **Impact:** Rapid clock hand rotation uses stale values of minutes/hours, causing the clock to jump unexpectedly between AM/PM or reset minutes to previous states while dragging.
- **Remediation:** Synchronize ref values directly inside the callback functions instead of relying solely on post-render `useEffect`.

---

### 2.2 Inconsistent Duplicate Validation Error Highlighting
- **Location:** [`app/src/app/(tabs)/dashboard.tsx`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/app/(tabs)/dashboard.tsx#L630-L685) & [`calendar.tsx`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/app/(tabs)/calendar.tsx#L618-L685)
- **Description:** In the vocabulary draft expansion modals, `isDuplicateErr` is computed as:
  ```typescript
  const isDuplicateErr = Boolean(errorWord && normWord && normWord === errorWord.toLowerCase());
  ```
  If a user inputs a duplicate word, ALL text fields matching `errorWord` turn red, including the original valid word entry, confusing the user as to which entry needs correction.
- **Remediation:** Highlight only the secondary duplicate draft row by tracking duplicate row indices.

---

### 2.3 FSRS Date Cutoff Edge Case Across UTC & Local Device Timezones
- **Location:** [`app/src/services/fsrs.ts`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/services/fsrs.ts#L15-L40)
- **Description:** `getStudyDate` applies an Anki-style 4:00 AM day rollover cutoff in local time, but compares against raw UTC ISO timestamp strings received from the backend:
  ```typescript
  const parseSafeDate = (rawDateStr: string | null | undefined): Date | null => {
    if (!rawDateStr || typeof rawDateStr !== 'string') return null;
    const d = new Date(rawDateStr);
    return isNaN(d.getTime()) ? null : d;
  };
  ```
- **Impact:** Depending on the user's UTC offset, reviews recorded near midnight UTC can shift calendar day calculations in local time, leading to `elapsed_days` being calculated off by 1 day in `ts-fsrs`.
- **Remediation:** Standardize all FSRS date inputs into local midnight representation before calculating day differences.

## 🟡 3. Security & API Reliability Issues

### 3.1 User Enumeration Vulnerability in OTP Endpoint
- **Location:** [`server/src/controllers/auth.controller.js`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/server/src/controllers/auth.controller.js#L438)
- **Description:** `/api/auth/send-otp` returns a `404 Not Found` error when `isSignUp: false` and the email does not exist:
  ```javascript
  if (!existingUser) {
    return res.status(404).json({ error: 'No account found with this email. Please sign up first.' });
  }
  ```
  In contrast, `/api/auth/forgot-password` returns a generic `200 OK` message to prevent email harvesting.
- **Impact:** Attackers can probe `/api/auth/send-otp` to verify whether any email address has an active account on WordRoot.
- **Remediation:** Standardize responses across authentication endpoints to avoid revealing account existence.

---

### 3.2 Single Proxy Limitation in `trust proxy` Setting
- **Location:** [`server/src/app.js`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/server/src/app.js#L13)
- **Description:** `app.set('trust proxy', 1)` assumes only a single reverse proxy exists. When deployed on cloud platforms like GCP Cloud Run behind Cloudflare or API Gateways (2+ proxies), `express-rate-limit` can misinterpret client IP addresses or fail.
- **Remediation:** Configure `trust proxy` dynamically based on environment configuration or loopback ranges.

### 4.2 Missing Indexes on SQLite Database
- **Location:** [`app/src/db/database.ts`](file:///c:/Users/Dev/OneDrive/Desktop/wordroot2/app/src/db/database.ts#L12-L38)
- **Description:** The `words` table lacks indexes on `dateAdded` and `nextReview`.
- **Impact:** Filtering words by date added or sorting pending reviews requires full table scans as vocabulary grows.
- **Remediation:** Add SQLite indexes:
  ```sql
  CREATE INDEX IF NOT EXISTS idx_words_dateAdded ON words(dateAdded);
  CREATE INDEX IF NOT EXISTS idx_words_nextReview ON words(nextReview);
  ```
